## 3. 下一轮：验证与收敛

优先级定义：P0 为发布验收前需要解决的事项；P1 为可靠性与交互改进；P2 为按需求评估的后续扩展。先完成 P0，根据测量结果安排 P1。

### P0-1：远端 CI 与可复现构建

- 依赖：代码进入能触发仓库 workflow 的分支或 PR。
- 工作：运行现有固件 workflow，确认依赖获取、默认构建、主机测试、资源检查和镜像归档。
- 验收：保留成功运行链接、对应提交及产物；失败时修复后重新验证。workflow 文件存在不能记为 CI 已通过。

### P0-2：设备冒烟、配置保存与升级

- 依赖：可连接的 S3 开发板及固件、SPIFFS、字体镜像。
- 工作：执行无凭证配网、后端配置、正常轮播、单击/双击、0 分退出、评分失败恢复、候选内容等待和页面切换。
- 工作：验证标准旧 URL 迁移、未知合法旧 URL 提示、新结构配置损坏/非法旧值/读取失败后的修复入口与 `config_state`，以及固件升级保留凭证。使用专用测试配置执行可能覆盖数据的场景。
- 验收：记录板型、固件提交、配置路径、可见结果及 `/api/status`；配置保存成功后重启生效，失败不报告成功，标题与当前内容一致，无错误切图或复位。

### P0-3：真实 WiFi、HTTP/TLS 与管理请求故障矩阵

- 依赖：设备冒烟通过；可控制的路由器及测试服务。
- 工作：验证 AP 消失/恢复、错误密码、DHCP 延迟、主动重连、退避和救援 AP；离线保留当前画面，恢复后继续获取。
- 工作：验证慢响应、断流、分块响应、3xx/503、超限与截断内容、损坏及尺寸错误 JPEG、TLS 证书错误、评分失败；验证管理请求分片、转义和超长输入。
- 验收：设备保持可用，响应边界有效，错误和降级可辨别；API headers 不发送给图片主机，重定向按当前拒绝策略处理，配置请求失败不会显示保存成功。
- 记录：每个场景的输入、预期结果、实测结果和恢复方式。接口替身测试与真实网络结果分别记录。

### P0-4：显示、字体与输入延迟测量

- 依赖：设备冒烟通过，能够提供不同复杂度的合法 JPEG 和测试字体资源。
- 工作：覆盖长标题、中文、标点、页面切换、评分恢复、字体不可用降级与标题滚动；测量整图解码/写屏耗时及按键到动作的最大延迟。
- 验收：图像、标题和底栏互不覆盖；字体失败可降级且不崩溃；记录延迟分布、最大值和丢键数，并确定交互可接受阈值。超过阈值时先修复再关闭本项。
- 注意：解码过程中定期让出 CPU，并不能证明输入已及时处理。

### P0-5：至少 24 小时运行与发布验收记录

- 依赖：前述板级故障和显示问题已收敛。
- 工作：持续轮播，周期性断网恢复并触发失败重试；记录空闲堆、历史最低堆、最大连续块、任务栈余量、失败数和丢键数。
- 验收：无崩溃、看门狗复位或无法恢复的状态；重复相同负载后空闲堆与最大连续块无持续下降，栈保留测量后确定的安全余量。计数增长需能关联具体故障和恢复结果。
- 交付：记录提交、板型、持续时间、采样间隔、日志位置、资源趋势及未关闭问题；全部 P0 完成后再标记首轮重构通过发布验收。

## 4. 本轮已落地（2026-10-28 第二轮）

硬件条件不可用期间，先完成可本地验证的 P1 事项；板级验收仍按第 3 节执行。

| 事项 | 落地内容 | 证据与边界 |
| --- | --- | --- |
| 存储异常恢复完善 | 配置加载区分 8 种状态；损坏、非法旧值、非法旧地址、读取失败、存储不可用一律保留原始 NVS 值并以默认配置开放配网入口，只有显式保存覆盖；`legacy_invalid` 保留原文供诊断 | 主机故障注入 8 个场景；实机降级恢复待 P0-2 验证 |
| 多设备 ID 策略 | `CONFIG_DEVICE_ID` 默认留空，首次启动由芯片 MAC 生成 `esp32s3-<12位hex>` 并随配置保存；显式标识（页面或旧 URL）永不被改写 | `config_model_default_device_id` 单测与首次启动写库断言；实机重启一致性待 P0-2 |
| Go 后端评分协议 | 修复 `server/api/rating_test.go` 与请求结构体同名的编译错误，补齐订阅源种子数据，新增“评分不推进设备条目”用例 | `go test ./...`、`go vet ./...` 通过；真实设备评分链路待 P0-2 |
| 历史路径清理 | 删除 `lib/image_fetcher`、`lib/rss_reader` 与空的 `lib/anim_player`；`check_firmware.py` 改为校验 `lib/` 下每个注册组件都进入构建 | 默认构建、资源检查通过 |
| 显示刷新收敛 | 统一底部 2px 的写入路径并记录当前内容，仅在内容变化或区域被覆盖后重写；删除未使用的进度条、成功页、字体测试页与 `ui_animation_write_row` 公共接口 | 构建通过；实际刷新时序待 P0-4 板上观察 |

## 5. 后续迭代候选

| 优先级 | 事项 | 依赖与验收条件 |
| --- | --- | --- |
| P1 | 解码期间的交互响应 | 依据 P0 延迟测量决定是否增量解码或分批调度；保持 UI 唯一所有者，修改后重复延迟及显示验收 |
| P1 | 自动化真实网络回归 | 从板级故障矩阵选取高价值案例建立可重复测试，覆盖真实传输；不重复堆叠仅验证接口替身的用例 |
| P2 | 图片鉴权及重定向 | 有实际内容源需求后定义主机范围、跳转次数和凭证规则；验证跨主机跳转不会附加 API 凭证 |
| P2 | 动态缓冲复用 | 依据长测中的分配失败、碎片或耗时决定；比较相同负载下最大连续块与峰值占用，避免无依据预留 RAM |
| P2 | 显示实现进一步统一 | 依据刷新问题和维护成本评估 LVGL 适配拆分或统一渲染；先验证内存预算，不默认引入全屏双缓冲 |
| P2 | 原生 `idf.py` 支持 | 需求明确后补齐依赖获取、资源生成、完整烧录和空目录验收；验收前继续以 PlatformIO 为正式入口 |

评分能力已由仓库内 Go 后端提供（`next` 返回 `item_id`，`POST /v1/item/{item_id}/rating` 落库）。无 `item_id` 的兼容路径仍然可用：内容正常展示，评分显式失败且不发送请求。

## 6. 维护规则

每项工作以可独立验证的变更推进，随相关逻辑补充必要测试。协议、配置格式和资源格式发生变化时，记录兼容条件与迁移行为。

关闭任务时更新本文件中的状态，并在 [固件开发与验收](firmware.md) 记录命令、设备条件、结果和证据。架构或所有权变化同步更新 [重构方案](firmware-refactoring.md)。未经执行的测试保持待执行；实现完成、测试通过和发布验收分别记录。
